# 0000 設計書は深さ3まで人が書く

- 状態: 採用
- 日付: 2026-11-16

## 決めたこと

人が書く設計は、サービスメソッドまでです。それより細かい分岐は、コードをAIが読みます。

図の基本は Mermaid です。スイムレーンだけ PlantUML の `|レーン名|` 形式にします。

図の変換は、開発者のマシンと GitHub Actions の中だけで行います。図の中身は、PlantUML.com や Kroki に送りません。

`main` にマージされたときだけ、変わったAPIの `変更履歴.md` に `YYYY-MM-DD #PR番号 PRタイトル` を1行足します。読み物サイトも、`main` だけを GitHub Pages に出します。

## なぜか

設計書が実装の写しになると、すぐに古くなります。例として、`checkOwner()` の目的が「公開してよい人だけ次へ進める」と分かれば、確認済みかの式は `src/services/profile.ts` を読めば足ります。

スイムレーンは PlantUML の `|ユーザー|` が短いです。画面とAPIの順番、分かれ道、データ、状態は Mermaid の方がリポジトリの差分で追えます。

図を外部サーバーへ送ると、未公開の業務が外に出ます。jar と Graphviz を Actions の中で動かせば、図のテキストはリポジトリの外へ出ません。
