ログインAPI（`POST /sessions`）の、API単位のテストです。

## 対象と前提

- 対象：[ログインAPI](../../apis/login/処理詳細.md)（`POST /sessions`）
- 前提：
    - 環境：検証環境 `https://api.example.com`
    - テストデータ：
        - 登録済み：メールアドレス `masato@example.com`、パスワード `example-password`。失敗回数は 0。ロック中ではない
        - 未登録：メールアドレス `unknown@example.com`
        - ロック中（登録済み）：メールアドレス `locked@example.com`、パスワード `example-password`。連続5回失敗から15分以内
        - ロック中（未登録）：メールアドレス `locked-unknown@example.com`。連続5回失敗から15分以内
        - ロック解除済み：メールアドレス `unlocked@example.com`、パスワード `example-password`。連続5回失敗から15分が過ぎ、失敗回数は 0 に戻っている
        - メール送信サービスは、U-10 以外ではログイン通知メールを受け付ける
        - 各ケースの実施前に、そのケースが使うテストデータの状態へ戻す

## 観点一覧

| 観点 | 確かめること | 対応ケースNo |
| --- | --- | --- |
| リクエストの形 | 条件に合わない本文は `400`（`INVALID_REQUEST`）になり、失敗回数は増えないこと | U-01、U-02 |
| ロック中の拒否 | そのメールアドレスがロック中のときは、パスワードが正しくても `403`（`ACCOUNT_LOCKED`）になり、失敗回数とロックの期限は変わらないこと。未登録でも同じこと | U-03、U-04 |
| 認証の失敗 | メールアドレスとパスワードが異なり、連続失敗が4回以下のときは `401`（`INVALID_CREDENTIALS`）になり、失敗回数が1増えること。どちらが違うかは返さないこと。未登録でも同じこと | U-05、U-06 |
| 連続失敗によるロック | メールアドレスとパスワードが異なり、連続失敗が5回目のときは `403`（`ACCOUNT_LOCKED`）になり、ロック（例：15分）を保存すること。未登録でも同じこと | U-07、U-08 |
| 認証の成功 | メールアドレスとパスワードが合い、ロック中でないときは `200` とセッションの Cookie を返し、失敗回数を 0 に戻し、ログイン通知メールを送ること | U-09、U-11 |
| 通知メールの失敗 | ログイン通知メールの送信が失敗しても、ログインは `200` のままで、セッションは取り消さないこと | U-10 |
