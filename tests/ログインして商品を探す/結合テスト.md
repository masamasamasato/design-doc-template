# ログインして商品を探すの結合テスト

業務フロー「ログインして商品を探す」の、画面から API、外部サービスまでのテストです。

## 目次

- [対象と前提](#対象と前提)
- [観点一覧](#観点一覧)
- [テストケース](#テストケース)
- [実施記録](#実施記録)

## 対象と前提

- 対象：[ログインして商品を探す](../../docs/business/ログインして商品を探す/README.md)
- 使うAPI：[ログインAPI](../../apis/login/処理詳細.md)（`POST /sessions`）、[商品検索API](../../apis/search-products/処理詳細.md)（`GET /products/search`）
- 前提：
    - 環境：検証環境 `https://www.example.com`、API `https://api.example.com`
    - テストデータ：
        - 登録済み：メールアドレス `masato@example.com`、パスワード `example-password`。失敗回数は 0。ロック中ではない
        - ロック中：メールアドレス `locked@example.com`、パスワード `example-password`。例：連続5回失敗から15分以内
        - 公開中の商品：`product_1001`、名前「木製デスク」、価格 19800
        - 非公開の商品：`product_1002`、名前「下書きデスク」、価格 9800
        - 名前に「ランプ」を含む公開中の商品は 0 件
        - メール送信サービスは、I-10 以外ではログイン通知メールを受け付ける
        - 各ケースの実施前に、そのケースが使うテストデータの状態へ戻す。ログイン状態も消す

## 観点一覧

| 観点 | 確かめること | 対応ケースNo |
| --- | --- | --- |
| ログインから検索までの通し | ログインできたあと、公開中の商品を検索語で探せること | I-01 |
| ログインの失敗 | ログインできなければ、検索には進まないこと | I-02、I-03、I-04 |
| セッションの検証 | ログインしていない、またはセッションの Cookie が無効なときは、検索できず `401`（`UNAUTHORIZED`）になること | I-05、I-06 |
| 検索条件 | 検索語や指定が決まりに合わないときは `400`（`INVALID_QUERY`）になり、検索結果は出ないこと | I-07 |
| 検索結果 | 公開中かつ名前に検索語を含む商品だけが出ること。0件のときも成功として空の結果が出ること。非公開の商品は出ないこと | I-08、I-09 |
| 通知メールの失敗 | ログイン通知メールの送信が失敗しても、ログインはでき、検索まで進めること | I-10 |
