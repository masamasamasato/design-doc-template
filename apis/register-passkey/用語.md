# 用語

このAPIだけで使う言葉です。共通の言葉は [用語集](../../用語集.md) にあります。

## チャレンジ

登録のときに一度だけ使う、短い期限の値です。期限は5分です。発行したときのログイン中の利用者に結びつけて保存します。使ったあと、または期限が切れたあとは、同じ値では登録できません。

## attestation

端末が、そのチャレンジに対してパスキーを作ったことを示す証明です。検証できると、公開鍵を保存します。

## origin と rpId

origin は、パスキーを使った画面のスキーム・ホスト・ポートの組です。例: `https://example.com`。rpId は、パスキーを結びつけるサービスのドメインです。例: `example.com`。どちらも自社のものでなければ、検証で落とします。

## user verification

端末で PIN か生体認証をして、端末の持ち主が操作したと確かめることです。登録でもログインでも必須にします。

## credential ID

保存したパスキーを識別する値です。例: `cred_88a1`。削除するときにも使います。

## 署名カウンタ

端末が署名するたびに増える数です。登録した時点の値を保存し、ログイン時に古い値になっていないかを判定します。

## 端末名

利用者が、登録したパスキーを見分けるための名前です。例: `雅人のスマホ`。例：30文字まで（Unicode のコードポイントで数える）。

## requireSession()

セッション検証のメソッドです。リクエストの Cookie を、保存済みの有効なセッションと比べます。無いか無効（例：ログインから24時間を過ぎた）なら `UNAUTHORIZED` を返し、この先の登録はしません。

## issueRegistrationOptions()

登録用のチャレンジを発行するメソッドです。1回限りで、期限は5分です。

## verifyAndSavePasskey()

attestation を検証し、公開鍵、credential ID、署名カウンタ、端末名を保存するメソッドです。秘密鍵は受け取りません。検証できなければ、保存しません。

## deletePasskey()

ログインしている本人のパスキーを削除するメソッドです。使わなくなった端末で、ログインできなくするのが目的です。最後の1つは削除しません。

## INVALID_CHALLENGE

チャレンジが無い、発行から5分を超えた、既に使った場合、または attestation がチャレンジ・origin・rpId・user verification と合わない場合の失敗です。登録はしません。

## INVALID_DEVICE_NAME

端末名が30文字（例：）を超える場合の失敗です。登録はしません。

## PASSKEY_NOT_FOUND

削除しようとした credential ID が無い場合、または他人のパスキーの場合の失敗です。どちらかは区別しません。

## LAST_PASSKEY

本人のパスキーが1つしか無いのに、それを削除しようとしたときの失敗です。削除しません。
